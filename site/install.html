Install Officefloor.

One pip install. Python 3.10 or newer. It runs on your machine, binds 127.0.0.1, and sends nothing anywhere.

Run it.

Installpip install officefloor
Open the demoofficefloor --demo
http://127.0.0.1:8788
Point it at your agentsofficefloor --allrepos ~/your/agents

Give it a folder of lanes.

Officefloor reads a directory where each agent has its own folder. A lane is any folder with an OUTBOX.md; engine prefixes are never required. Names with leading/trailing whitespace or control characters, starting with . or containing :, /, or \ are skipped (skipped: reserved character). Experimental --session-discovery (default off) also discovers git repositories with exact-path agent session evidence. The floor infers an engine badge from agent metadata and shows unknown when it cannot.

~/your/agents/
  frontend/
    INBOX.md      directives you write to the agent
    OUTBOX.md     the agent's reports, ending in a STATUS block
  backend/
    INBOX.md
    OUTBOX.md

The floor also reads what it can measure on its own: the agent's process, its git branch and last commit, and how long ago each file was written. If it cannot measure something, the seat says unknown.

Tell your agents how to report.

Append the reporting protocol to each agent's instruction file. The package ships it, so the text on your machine is always the version your floor parses.

officefloor --agent-md >> ~/your/agents/frontend/CLAUDE.md

The whole contract is one rule: end every report to OUTBOX.md with this block. The floor reads from the last line that is exactly STATUS to the end of the file.

STATUS
branch: <your working branch>
ready_for_pr: true|false
decision_needed: <short question, or null>
blockers: <one line, or none>
task: <what you are doing>
next: <one line>
ready_for_prtrue, yes, or 1 lights the seat as holding finished work for you to collect.
decision_neededanything other than null, none, or no renders the agent as asking you a question.
blockerssame rule. A blocked seat shows as blocked, never as idle.
INBOX newer than OUTBOXthe agent owes you a reply, and the floor says so.

A prompt you can paste as-is, for any harness:

You report to a floor that reads your OUTBOX.md. Log status and findings
there as you go. End EVERY report with the literal STATUS block: a line that
is exactly STATUS, then branch, ready_for_pr, decision_needed, blockers,
task, next, one per line. Report truthfully or not at all; the floor
never invents facts about you. When you need a decision, write a DECISION
NEEDED <id> paragraph and put the question in decision_needed too. Read
INBOX.md for directives and answer each one in OUTBOX.md.
